## 一、一直搞错的一个点

之前我认为留给sft的轨迹都是那种专家轨迹，就是一点路都没有绕过的，每一条都是示范轨迹。但是真实情况往往不是这样的，真实情况下需要保留合理的探索，合理的探索不能简单当成绕路来进行删除，不能让模型凭空知道怎么做，应该是过程正确，信息充分，成本合理。

还有就是出现了错误，不一定需要整条进行淘汰，识别问题并且回复也是工具使用能力，不能全部洗掉。

需要判别的是：**终态满足要求和执行过程是否值得模仿**这两个点

## 二、确定固定候选池，然后先用代码做确定的清洗

之前使用gpt6-luna跑了3000个问题（花了50刀，心在滴血）

其中有966条是通过的，使用代码先做一些确定的清洗

检查轨迹、任务等，去掉独立推理字段等，保存真实上下文等，**主要完成的任务是基础检查和整理**

剩下的就是交给LLM进行一个数据清洗
对每个轨迹进行一个打标签：分为keep和reject。

流程大概是这样

```
成功候选轨迹
    ↓
代码基础检查 + Codex 审核
    ↓
合格 → keep
有问题 → 能可靠修复就修复，再检查
                       ↓
                 合格 → keep
          不合格或无法确认 → reject
```

对于删步骤这方面，我感觉需要保守点。第一版不删步骤了，因为我觉得模型需要保留的合理的研所，默认保留步骤，审核整条质量，合格就keep，不合格就reject。错误步骤保留给模型看，但是不要求模型学着输出这个动作，要求学习它后面是怎么修正的。也就是说包含明确错误但恢复有价值的，保留上下文并标记不监督的错误动作。

## 三、总体清洗流程

1. 筛出真正成功、过程合格的轨迹。
2. 去掉独立推理字段、评测分数、用量等外围信息。
3. 检查上下文和调用返回是否完整、对应。
4. 确定哪些教师模型产生的动作参与训练。

## 四、llm负责什么

主要做语义和过程审核：结合题目、工具规则及每一步的实际返回，判断这条轨迹是否适合作为 SFT 示范。

让 LLM输出keep／reject + 原因 + 证据位置

## 五、我项目的做法

数据怎么来？
3000道题先跑一次，如果环境有问题的直接筛掉，保留了966到题，其中966道题里面只有758条是做对的，所以这些用于sft轨迹。
758条轨迹里面，教师模型一共回复了7071轮，然后审核时又357轮是不让学习的，每轮做成一个sft训练样本。

数据可信性？

1. 代码匹配每次模型请求和当轮实际收到的信息
2. 把模型的响应和原始输出对上
3. 把工具名，参数，调用和返回对上

然后再llm再来进行判断，如果让模型模仿这一波，学到的行为是否合理，结合题目，工具规则和逐轮可见信息来审核

训练时练什么？
读取该轮的输入，教师模型的输出，再当前回复上计算loss

最后结果：
跑了16个checkpoint，lr分别是1e-5和2e-5，batchsize是64，选择其中的一个在验证集表现最好的模型去跑测试集
