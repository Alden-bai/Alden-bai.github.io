# 布吉熊的小窝

个人学习主页与 Markdown 笔记站，使用 VitePress 1.6.4。目标地址：<https://alden-bai.github.io/>。

保留 VitePress 稳定版，同时将构建依赖 Vite 和 xmldom 固定到包含安全修复的版本；依赖锁定在 `package-lock.json`。

## 本地预览

需要 Node.js 22 或更新版本。在本目录打开终端：

```sh
npm ci
npm run dev
```

生产构建与预览：

```sh
npm run build
npm run preview
```

打开终端显示的本地地址。添加、同步或重命名笔记及专区后，重启开发服务以刷新导航、侧边栏和专区路由；正式构建会自动重新扫描。

## 添加笔记

1. 在 `docs/notes/<专区名>/` 中添加 UTF-8 编码的 `.md` 文件（扩展名使用小写），例如 `docs/notes/强化学习资料/first-note.md`。新增第一级目录即新增专区，无需修改导航配置。
2. 可在 YAML frontmatter 中设置 `title` 作为笔记标题；未设置时使用第一个一级标题，再回退到文件名。
3. 运行 `npm run build` 检查，再提交并推送到 `main`，GitHub Actions 会自动发布。专区按名称排序，文章按标题排序。

示例（仅用于说明，不会作为文章发布）：

````md
# 我的第一篇学习笔记

## 核心概念

在这里写自己的理解。

行内公式：$E = mc^2$。

$$
\sum_{i=1}^{n} i = \frac{n(n+1)}{2}
$$

## 代码示例

```python
print("保持好奇")
```
````

`docs/notes/index.md` 是专区总览，请保留。首页卡片、总览、独立专区页及阅读侧边栏共用 `.vitepress/note-index.mjs` 的分类数据。专区地址为 `/sections/<专区名>.html`，文章地址仍为 `/notes/<原有路径>.html`；中文和空格会自动编码。

专区内的子目录显示为分组；空目录、隐藏目录和系统目录不会显示。直接位于 `docs/notes/` 下的文章归入“其他笔记”（与同名专区合并）。标题中的常见 Markdown 标记会被去掉；没有一级标题时使用文件名。上一篇和下一篇仅在同一专区内跳转。

首页和全部专区卡片显示专区内最近的上传日期，专区列表在每篇标题下显示该篇日期，格式为“最近上传于 2026年9月23日”；阅读页不额外增加日期。日期采用该笔记文件最近一次 Git 提交时间，按北京时间（Asia/Shanghai）显示，代表成功发布版本对应的内容提交日期，不是部署完成时间。只修改样式或重新构建不会改变笔记日期。新文件提交前显示“待上传”；没有 Git 历史或只有浅克隆历史时显示“上传日期暂不可用”。GitHub Actions 使用完整历史构建，发布前应先提交笔记，再构建检查正式日期。

## 在外层目录写作与同步

力扣笔记继续在 `../力扣刷题/` 中编辑，网站里的 `docs/notes/力扣刷题/` 是同步副本，请不要直接修改。已有的强化学习与 Agentic RL 笔记仍在 `docs/notes/` 对应目录中编辑。

从本网站目录运行：

```sh
# 先查看变动，不写入任何文件
npm run notes:sync -- --dry-run

# 同步，再执行含公式检查的完整构建
npm run notes:sync
npm run build
```

新建外层专区时，在 `notes.sources.json` 增加一项，例如：

```json
[
  { "section": "力扣刷题", "source": "../力扣刷题" },
  { "section": "计算机网络", "source": "../计算机网络" }
]
```

来源路径相对于 `website/`，专区名对应网站笔记目录。同步会复制 Markdown 及其相对引用的本地图片、附件，保留子目录和原稿内容；不下载外部链接，不扫描未登记的外层目录。附件必须在对应来源目录内；隐藏文件、符号链接、越界引用或丢失附件会被跳过或报告，不能静默发布失效附件。

`.notes-sync.json` 记录受管理副本和内容摘要，必须随网站一同提交。再次同步只更新这些副本；原稿删除时，只删除未被单独修改过的对应副本。同名未管理文件、网站副本被修改或删除、来源目录缺失都会停止整次同步并指出文件。发生冲突时，先比较并把想保留的修改合并到原稿，再用 Git 恢复对应网站副本和同步记录到上次一致状态，重新运行同步；不要删除同步记录来绕过检查。移除一项来源配置会停止管理该来源，不自动删除已发布文章。

确认构建和预览后，提交网站内容、来源配置和同步记录，推送 `main`。同步命令不会自动提交或发布；GitHub Actions 只构建仓库中已同步的文件，不访问你电脑的外层目录。单纯编辑原稿不会自动更新线上内容，需要重新同步并发布。

## 公式书写与发布检查

公式支持以下四种写法，粘贴笔记时无需手工替换定界符：

| 类型 | 推荐写法 | 兼容写法 |
| --- | --- | --- |
| 行内公式 | `$A_i = \frac{r_i}{s}$` | `\(A_i = \frac{r_i}{s}\)` |
| 独立公式 | `$$ ... $$` | `\[ ... \]` |

长公式建议独占一个公式块；多行公式使用 `aligned` 等 LaTeX 环境。公式块不要缩进四个空格（Markdown 会把它当作代码块）。在表格单元格中出现竖线时，优先使用 `\mid` 或 `\vert`，避免被 Markdown 当作分栏符。

公式在构建时生成 SVG，不依赖读者浏览器下载 MathJax 脚本。兼容和检查逻辑位于 `.vitepress/math.mjs`。

每次运行 `npm run build`（包括 GitHub Actions 自动发布）都会先执行公式回归测试、检查全部现有笔记，再构建页面。未闭合的公式定界符、错误的 LaTeX、未知命令，以及正文中遗漏公式定界符的常见 LaTeX 命令会导致检查失败，日志以 `[公式检查]` 标出文件及错误原因；构建失败不会覆盖线上版本。也可以运行 `npm test` 单独检查。

如果只是介绍公式源码、命令或 `$HOME` 这样的变量名，请使用反引号或代码块包裹；普通美元金额如 `$5` 不受影响。检查无法推断所有书写意图，发布前仍建议用 `npm run dev` 看一下新增笔记。

## 插入图片与链接

把图片放在笔记旁边的 `images` 子目录，用相对路径引用：

```md
![示意图的文字说明](./images/example.png)
[另一篇笔记](./another-note.md)
```

也可以把公共图片放在 `docs/public/images/`，用 `/images/文件名.png` 引用。不要直接链接电脑上的绝对路径。普通文字中包含 `<`、`>` 或 `{{ }}` 时，使用行内代码包裹，避免被当作 HTML/Vue 模板。

## GitHub Pages 发布

1. GitHub 仓库名称必须为 `Alden-bai.github.io`（从原 `bjx.github.io` 改名），对应账号根地址。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 本目录作为独立 Git 仓库，远程地址为 `https://github.com/Alden-bai/Alden-bai.github.io.git`。
4. 推送 `main` 后，在 **Actions** 查看部署结果；成功后访问 <https://alden-bai.github.io/>。

工作流位于 `.github/workflows/deploy.yml`，支持手动运行。仅上传 `docs/.vitepress/dist` 静态产物。失败时线上仍保留上一次成功版本；修复后重新推送即可。

## 内容边界

只有网站内容以及明确登记并执行同步的来源会进入网站仓库。未登记的外层目录不会被自动复制或发布。本站公开访问，不包含后台、评论、统计或上传功能。暂未为个人笔记授予开源许可证。
